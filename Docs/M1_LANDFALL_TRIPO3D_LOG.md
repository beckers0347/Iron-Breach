## Evacuee civilian — generated, rigged, walk-animated, exported

Not on the original district prop list (that list is all static-mesh
background dressing) — this is the generic carried civilian for the muster
point / carry mechanic, generated separately as a skeletal character:

1. Text to 3D → generic adult civilian, T-pose enabled.
2. 3D Rigging & Animation tool → Auto Rig, model **v2.5 - Good for Animals**
   (20 credits) → came back `Model Type: Humanoid`.
3. Searched animation presets for "walk" → one result → applied it →
   retargeting completed (~34s), checkmark shown on the "walk" thumbnail.
4. Export → FBX, 3dsmax orientation preset, Export Skeleton ON.

**Gotcha, confirmed by hand:** the Export dialog's "Number of Animations"
field defaults to **0** even with a retargeted animation applied and showing
a checkmark on its own thumbnail in the Animate panel. The walk clip is not
actually included in the export until you click into the "Number of
Animations" row, which opens a separate "Choose Animations" panel, and
explicitly check the animation there (0/1 → 1/1). Skipping this step exports
a mesh-only FBX with the walk animation silently dropped. If this asset (or
any future rigged+animated Tripo3D export) gets regenerated, don't trust an
unopened Export dialog — open Choose Animations and verify the count before
exporting.

Exported as `SK_Evacuee_Male_Walk.fbx`, confirmed by the "SK_Evacuee_Male_Walk
exported successfully" toast.

`SK_Evacuee_Male_Walk.fbx` and its texture set are now in
`Content/LevelPrototyping/AIModels_Landfall/`. Confirmed the animation
actually survived export by grepping the raw FBX for animation markers before
moving it in: the evacuee file carries `AnimCurveNode`/`AnimLayer` entries
(15 and 2 respectively), while `SM_Stretcher.fbx` — a static prop — has none,
which is the expected signature difference between an animated skeletal
export and a static mesh export.

Import handled by a new script, `import_m1_landfall_evacuee.py` (skeletal
mesh + AnimSequence import — different asset shape than the district props,
so it isn't folded into `import_m1_district_ai_models.py`). Both import
scripts are now unblocked and ready to run.

**Future follow-up, not done yet:** the mission doc's own convention warns
against a visible "clone army" of identical civilians at the muster point.
This first pass is one generic evacuee; if the muster point ends up needing
more than one body on screen simultaneously, generate 1-2 more variants
(different build/coloring) through the same Auto Rig + walk pipeline before
that becomes visually obvious in a playtest.
